## 主代理如何分配任务

主代理持有总体计划和验收责任。可以让较简单模型完成清楚的小步骤，但任务包不能只是“实现整个评估器”。

推荐分配粒度：

| 工作 | 简单执行模型可以做的部分 | 主代理必须完成的部分 |
|---|---|---|
| T0 基线 | 读取状态、列文件和测试结果 | 合并策略、冲突解决、回归解释 |
| T1 CI | 按已批准完整内容录入文件 | action 来源核查、权限审查、发布 |
| T2 样本 | 录入已批准表格、校验字段 | 上游调查、缺陷与对照定性 |
| T3 prepare | 按契约实现纯校验、fixture 测试 | 路径安全和上传边界审查 |
| T4/T5 API | 可在主代理流程中完成明确编码步骤 | 凭证/网络边界、预算、失败语义 |
| T6 score | 已定公式的纯函数、手算 fixture | 指标定义、真实 finding 裁决 |
| T7 live | 整理不含密钥的已完成记录 | 上传/付费授权、真正联网调用 |
| T8 报告 | 按已审核数字和结论排版 | 结论、限制、发布与后续范围 |

上表是一般执行模型的分工建议，不覆盖 AGENTS.md 对 Luna/Harness 的更严格限制。

## 人工实际需要提供什么

- 开始实施计划的指令，以及遇到关键判断时可复核的主代理/人工。
- T2：主代理调查和核查后的真实样本标签；不要求用户自己搜代码。
- T7：在执行环境配置 API Key，以及明确的模型/上传范围/调用额度授权。
- 发布时：当前分支对应的推送或合并授权。先完成可审阅的代码和测试再进入这个环节。

这份计划不会代替人工确认缺陷，也不会把使用更小模型等同于可以完全无人监督。
