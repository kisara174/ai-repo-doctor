# AI Repo Doctor：Codex 调用与仓库关系图目标计划

日期：2026-10-01。基线：已发布并在 Mac 安装的 v0.4.1。下一里程碑建议版本：v0.5.0。

本文件定义本阶段的产品目标、工作顺序和完成条件。方案已通过并执行：新增命令、Skill 和图形功能已实现，v0.5.0 本地候选包已安装到 Mac。各阶段的实际状态见第 6 节；安装、流程证据及尚未确认的交付检查见[候选版交付记录](../../delivery/2026-10-01-v050-candidate.md)。已有发布与评估记录保留作为历史证据。

## 1. 产品目标与分工

**让 Codex 按需调用 Repo Doctor，获取可追溯的仓库结构、上下文和调查证据；让人通过离线交互 HTML 和 SVG 看懂仓库组成与静态关系。**

| 角色 | 负责的工作 | 用户获得的结果 |
| --- | --- | --- |
| Repo Doctor | 本地扫描、符号索引、结构摘要、静态关系、上下文裁剪、引文校验、调查记录和可视化 | 可检查、可保存、可重复生成的数据与图 |
| Codex | 阅读上下文、判断问题、提出方案、编辑代码、选择并运行必要检查、解释结论 | 完整的代码调查和修复工作 |
| 人 | 查看项目结构与关系图、了解静态分析覆盖范围 | 直观了解仓库组成和关系 |

主要使用路径不需要 DeepSeek API Key，也不由 Repo Doctor 再调用另一个模型。现有 DeepSeek 入口保持为可选能力，其准确率提升不再是本阶段交付前提。自动诊断、自动生成或应用补丁不纳入本阶段目标；修改仓库由 Codex 在用户授权范围内完成。

本阶段继续聚焦本地 Python 仓库、可 pip 安装的 CLI，以及已经部署的 Mac 使用方式。

用户执行前补充：面向人的页面只需要项目结构关系图；其他详细调查交给 Codex。页面不增加诊断、问题管理或补丁面板。

## 2. 两个必须闭环的用户流程

### A. Codex 调查流程

```text
用户提出仓库结构或代码调查需求
  → Codex 通过 Skill 调用 CLI
  → 获取有界概览、检索目标符号、获取上下文与影响关系
  → Codex 阅读证据并形成判断
  → 有发现时校验并保存到同一调查报告
  → 需要修复时由 Codex 修改、运行针对性检查并记录结果
  → 返回带路径、行号、证据状态和分析边界的结论
```

结构问答可以直接结束，不要求每次产生 issue。没有足够证据时明确保留假设；引文匹配成功不等于缺陷成立，检查退出码也不自动证明根因或修复完整。

### B. 人阅读仓库流程

```text
仓库路径 → 生成一个地图目录
  → 直接打开 map.html
  → 在结构树与关系图之间切换
  → 搜索、展开、查看节点与局部关系
  → 查看默认 SVG，或导出当前筛选视图的 SVG
```

用户已确认交付形式：**交互 HTML，同时导出 SVG**。HTML 离线打开，不要求启动服务；SVG 可以单独查看和分享。

## 4. Codex 接入方案

### 首版：CLI JSON + Codex Skill

现有 CLI 已可由 Codex 的终端工具调用，首先完善调用约定和发现入口。

Skill 包含适用场景、命令顺序、如何选择符号、输出预算、错误处理、证据解释和保存报告的方法。它引导 Codex 在仓库结构、调用追踪、改动影响和有证据的代码调查需求中使用工具；简单编辑或无关问答无需调用。

Skill 支持按描述匹配任务，也保留显式 `$repo-doctor` 调用方式。隐式匹配不是每次必然触发，因此文档须给出明确调用方法和排错步骤。Skill 文件随 wheel 发布，提供导出到用户 Skill 目录的安装步骤，不覆盖既有 AGENTS 规则和全局配置。[官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)说明了描述匹配、显式调用和用户目录 `$HOME/.agents/skills`。

本地候选版已实现以下入口，具体说明见 [Codex 与地图使用指南](../../CODEX_AND_MAP.md)：

```text
repo-doctor overview REPO --json
repo-doctor context REPO SYMBOL --snapshot-out FILE --json
repo-doctor findings import CASE --from FILE --context SNAPSHOT --producer codex --json
repo-doctor map REPO --out DIR [--symbol SYMBOL] [--depth 1|2]
repo-doctor skill export --out DIR
```

`overview` 返回有限长度的结构摘要、扫描范围、静态审阅入口和后续命令提示。它复用现有架构与审阅入口逻辑，不将完整 `scan --json` 作为默认输入。列表需有总量、返回量、截断标识；不把文件缺失或未解析调用直接标为 bug。

上下文快照记录仓库标识、源码指纹、目标符号、实际选中片段及内容哈希。导入发现时检查快照是否仍对应当前源码、引用是否属于快照，以及文件、行号和引文是否匹配。快照过期或引文无效要明确拒绝或标注原因，不静默当作已校验。

导入后的 issue 使用现有稳定 ID 和报告机制，默认待复核，生产者记录为 Codex；不伪造 DeepSeek 请求或模型信息。Codex 的复核与用户亲自确认须可区分。导入只接受结构化数据，不触发其中附带的命令；复现和修复检查仍通过现有显式入口运行。不得通过手工改写 case JSON 绕过这些入口。

### 后续适配：本地 stdio MCP

只有在需要原生工具列表、跨客户端接入或 CLI 编排出现具体障碍时，再实现薄 MCP 适配层。它调用同一服务和数据契约，不复制扫描器或重新设计产品流程。Codex 官方支持本地 stdio MCP；届时可按[官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)配置。

MCP 不作为本阶段首版的完成前提；本次计划也不修改用户的 MCP 配置。

## 5. 地图的数据与交互要求

### 同一数据源、两种视图

| 视图 | 展示内容 | 默认浏览方式 |
| --- | --- | --- |
| 结构树 | 目录 → 文件/模块 → 类、函数、方法 | 先显示目录与文件，按需展开符号 |
| 关系图 | 导入、已解析调用、重导出和注册关系，分别标识类型 | 先看文件关系，再查看选定符号的调用者与被调用者 |

README、配置和 CI 文件可作为仓库组成的路径元数据纳入结构树，不承诺解析其语义，也不默认读取或嵌入其内容。文件发现复用现有忽略、目录排除和不跟随符号链接的规则。

每个符号节点有稳定标识、相对路径和源码范围。每条导入、调用或语义关系在地图数据中保留其源码证据位置；目录包含关系单独标识，文件级聚合关系保留实际证据供 Codex 查阅。箭头图例明确方向，例如“调用者 → 被调用者”和“导入者 → 被导入模块”。

显示扫描错误、未解析调用、歧义与覆盖范围，不能补画不存在的关系。图是静态分析结果，不声称包含运行时的全部调用；不凭文件名猜测架构职责，不添加无依据的健康分数。

### 必需交互

- 搜索目录、文件和符号；搜索结果可以定位并展开相关区域。
- 展开/收起结构，切换结构树与关系图，缩放和平移。
- 筛选关系种类，控制是否显示测试文件。
- 选中节点后显示结构位置与局部关系；详细证据保留在地图数据中供 Codex 使用。
- 限制当前视图规模并显示隐藏数量。初始建议上限为 200 个节点、500 条连线，符号邻域深度为 1 或 2；实现时依据真实仓库可读性调整并记录理由。

不把全部符号一次塞进关系图。搜索、筛选和展开应让用户逐步定位目标，而不是让用户在一团连线中寻找文件。

### HTML 与 SVG 交付

每次地图生成至少产生：

```text
map.json       版本化的数据与来源元信息
map.html       内嵌数据和资源的离线交互页面
structure.svg  默认结构概览
relations.svg  默认关系概览
```

HTML 使用内嵌 SVG 展示节点和连线，浏览器可导出当前筛选、展开状态对应的 SVG。命令行同时生成两张默认 SVG，不能仅交付一个以后再导出的按钮。

HTML 和所有 SVG 使用同一地图投影与视图定义。导出保留节点、箭头、图例、相对路径、源码版本/指纹和截断说明，不包含界面按钮。SVG 自包含，不依赖外部样式、字体服务或脚本。

HTML 在 Safari、Chrome 中以 `file://` 打开即可使用，不依赖后端、CDN、在线请求或 npm 安装。默认仅保存所需结构元数据，不嵌入整仓源码。处理路径、符号名和其他仓库文本时必须正确转义，不能让其成为页面脚本或 HTML；分享前能看清地图包含哪些信息。

Python 核心继续保持现有运行依赖和支持版本。小型 JS/CSS/模板资产随 wheel 打包；不为这一阶段引入常驻服务。

验证围绕下列用户结果，不为追求测试数量反复开展无关实验。修改影响现有接口时才补充相应回归检查，并满足项目已有发布门槛。

| 要证明的结果 | 使用的材料与操作 | 保留的证据 |
| --- | --- | --- |
| 静态地图可追溯 | 小型多文件受控仓库，含导入、直接调用、重导出、注册和未解析情况；逐项对应源码 | 预期关系与实际地图，边的文件/行号，未知与截断说明 |
| Codex 可以调用和保存 | 已有离线演示仓库；一次显式 Skill 调用与一次自然语言结构需求；无 Key 走到上下文和发现导入 | 实际命令记录、快照、issue 来源及重开的报告；记录是否触发隐式匹配 |
| 调查与修复职责分明 | 已有受控缺陷，由 Codex 判断和修改，Repo Doctor 记录针对性的修复前后检查 | Codex 修改 diff、前后检查与源码版本；证据不足时保留未验证状态 |

不要求在真实仓库凭空找到新 bug，也不把已知缺陷提示后识别出来当作自主发现。只在有明确质量问题时追加相关验证；本阶段不开展新一轮 DeepSeek 盲测。

最终成品应能让用户提出：

> “用 Repo Doctor 帮我理解这个 Python 仓库，生成可以查看和导出的关系图；再分析指定函数的调用与影响。如果发现问题，由你解释证据、决定方案并执行我授权的修复。”

完成上述请求后，用户得到可浏览 HTML、可分享 SVG、可追溯数据和必要的调查报告；Codex 得到适合继续工作的上下文。任务没有修复需求时，图和结构解释本身就是完整产物。

## 8. 范围与执行纪律

- 既有云端诊断和报告记录继续保留，但旧路线中的模型优化、自动补丁不进入本阶段待办。
- 本阶段不加入多语言、运行时调用追踪、整仓自动修复、复杂 Web 平台或常驻 API 服务。
- 不承诺完整解析 Python 动态调用，也不在测量前承诺 token 节省比例或诊断准确率。
- 产品界面突出结构、路径、关系和未知范围；详细证据、命令编排和模型内部细节留给 Codex 与工具文档。
- 主代理负责需求、接口、设计、排错、风险、复核和发布。只有路径、机械步骤和独立验证已经明确的小任务，才按 AGENTS 规则路由给执行器；不能将本计划或架构判断交给 Luna。
- 执行时保留已有修改，按阶段修复实际阻塞。完成条件达成后继续下一阶段；若发现严重缺陷，先定位并修复与当前闭环相关的问题，再更新记录，不无限扩张范围。

下一项具体工作是完成剩余交付检查：在允许操作的原生浏览器直接打开最终 `map.html`，验证搜索、展开、筛选与下载的 SVG；确认新会话 Skill 的调用方式，再按发行提交核对 CI 并发布正式版本。已实现的 P1–P6 不重复实施，不增加新模型评估或自动修复范围。
