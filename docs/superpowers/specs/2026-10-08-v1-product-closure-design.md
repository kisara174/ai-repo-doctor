# AI Repo Doctor 1.0 产品闭环设计

日期：2026-10-08。状态：规划基线；尚未实施。主计划：[执行清单](../plans/2026-10-08-v1-product-closure.md)。

## 1. 目标与完成定义

交付可安装、可重复使用、可升级回滚的 `AI Repo Doctor 1.0.0`。Codex 调用工具获取静态源码证据并负责判断和修复；人类查看仓库结构关系图。

完成必须同时满足：

| 编号 | 用户结果 | 验收依据 |
| --- | --- | --- |
| A1 | 新用户按文档安装并确定实际运行的版本 | 干净虚拟环境、安装来源、CLI 绝对路径和版本回执 |
| A2 | Codex 从概览定位真实符号，获得上下文和影响证据 | 五个命令的真实调查记录，未知关系和截断明确说明 |
| A3 | 人类能查看结构和关系并导出 SVG | 离线 HTML、两种 SVG、交互投影一致性 |
| A4 | Python 与 JS/TS 支持边界一致且诚实 | 支持矩阵、错误行为、可重复的合同用例 |
| A5 | 正常规模能工作，超出边界可理解地失败 | 耗时记录、资源边界及超限失败回执 |
| A6 | 升级后能回到原版本，既有数据不丢失 | 版本化安装、切换/回滚实演、保护清单复核 |
| A7 | 公开发布物来自精确提交且可安装 | CI、wheel/runtime 对照、公开下载校验与独立安装 |
| A8 | 产品有明确分发许可和维护方式 | 许可文件、包元数据、CHANGELOG、问题反馈与兼容政策 |

发布成功只是 A7 的一部分。A1–A8 全部通过且没有未解决的发布阻塞，Goal 才能完成。

## 3. 产品范围

### 3.1 1.0 核心

1. `overview`：有界仓库概览。
2. `symbols`：搜索并返回真实符号 ID。
3. `context`：指定符号及相关符号的预算内源码证据。
4. `impact`：静态已解析关系的有界影响查询。
5. `map`：离线结构/关系 HTML 与 SVG；默认节点 200、边 500 的投影上限保持。
6. `--version`、`--help`、`skill export` 及完整安装、升级、回滚说明。

Python 的已有案件/快照能力保留兼容，但不作为新用户的默认路径。已有诊断与执行命令保留清楚的次级说明；不增添自动诊断、自动补丁或自动执行目标项目的能力。

### 3.2 固定边界

- Python 默认开启；JS/TS 需要 `js` extra 并显式选择语言。
- JS/TS 实现文件：`.js`、`.mjs`、`.jsx`、`.ts`、`.tsx`；语法按扩展名选择。
- 动态回调、方法、运行时替换、部分包/别名和多跳导出等继续表示为未知。
- JSX 标签和事件引用不自动变成调用边；语法恢复文件不能泄漏部分已解析调用。
- JS/TS 不支持 Python 案件/快照流程；空影响不证明没有影响。
- 不新增语言、MCP 服务、托管网页、云诊断、GUI、收费/账户/支付系统。
- PyPI 发布可后续独立安排；GitHub wheel 的 pip 安装链必须先闭环。

## 4. 接口与兼容

以 CLI 及 JSON 为 1.x 稳定公共接口，Python 内部模块不是稳定 SDK。

- 从实际五个命令输出整理字段类型、可选性、符号 ID、行号、排序、语言元数据和截断语义。保留现有 schema_version 差异，不为整齐重编号。
- 保留已发布字段、类型和证据含义；新增字段允许消费者忽略。不得把不确定边改成确定边。
- 核心查询成功退出 0，参数/路径/缺依赖/超限等操作错误退出 2；其他命令已有退出 1 的含义单独记录。
- 核心 `--json` 成功时 stdout 只有一个 JSON 文档。失败沿用 stderr 错误说明、stdout 空，不另造统一错误 JSON 接口。
- 文件级解析错误可出现在成功的概览中，并明确计数/限制；整体资源超限必须使本次查询失败，不能伪装成完整结果。
- 删除字段、改变类型/ID 或缩小已承诺语义须进入下一个主版本；1.0 相对 0.8 的有意边界变化单列迁移说明。

## 5. 安装和 Skill 接入

采用标准 `venv + pip + 版本化目录`；不开发新的包管理器。

- 推荐完整环境安装带 `js` extra 的固定 wheel；纯 Python 环境不安装 native parser，仍独立验收。
- 用户文档不包含维护者用户名、工作树路径或仅本机可用入口。首次安装通过 wheel URL 与 SHA256 文件确定来源。
- 日常命令可以使用全局入口；调查与 Skill 使用已核验的版本化 CLI 绝对路径，避免误调旧 PATH。
- 扩展现有 `skill export`：增加可选 `--cli ABSOLUTE_PATH`。`export_skill(destination: Path, *, cli_path: Path | None = None) -> None` 保留旧调用方式。
- 绑定导出在新目录生成 `SKILL.md` 和 `installation.json`。后者固定为 `{schema_version: 1, cli: 绝对路径, version: 当前包版本}`；工具路径必须可执行且 `--version` 与当前包一致。错误不留下成功外观的导出目录。
- 模板保持可移植，删除维护者路径。Skill 先读取旁边的绑定信息并核对版本，再调用同一路径；不自动回退到旧 PATH。未绑定导出说明如何重新绑定。
- 1.0 导出 Skill 名称使用 `repo-doctor-v1`，与现有 `repo-doctor` 并存。文档明确在 Codex 中指定该 Skill，避免两个 Skill 的自动匹配被当作验证成功。
- 不覆盖现有用户 Skill；实际加载新 Skill 必须在干净会话核实，不能仅以导出文件存在作为接入成功。
- 升级先建新环境、验收、再切换入口；保存旧入口类型/链接值与旧环境。回滚恢复原入口并复核版本。已有普通文件入口不自动覆盖，由主代理制定保留方案。

## 6. 资源与规模

首版采用简单的失败边界，不引入持久缓存、服务进程或增量索引。

| 边界 | 初始产品值 | 行为 |
| --- | --- | --- |
| 单个被选中实现文件 | 2 MiB 原始字节 | 超限失败，报告文件和上限 |
| 被选中实现文件数 | 5,000 | 解析前超限失败 |
| 累计实际读取源码 | 64 MiB 原始字节 | 超限失败，不输出部分成功 |
| 单次 Git 子进程 | 15 秒 | 超时明确失败，不静默换扫描模式 |
| 索引与证据准备检查点预算 | 60 秒 | 阶段/文件边界检查并失败 |
| impact 查询深度 | 1–10 | 参数超限退出 2，默认仍为 2 |

这些是要通过 V3 实验确认的产品默认值，不是现有能力的描述。若真实支持用例触及边界，主代理依据记录调整设计和所有对应文档/测试，执行器不能自行放宽。

累计字节包括同次查询中指纹、上下文等再次读取，不按路径去重。预算从索引开始延续到证据准备；地图复用首次发现路径，不增加第二次扫描。

实现方向：新增内部 `AnalysisLimits` 和每次分析独立的 `AnalysisBudget`；使用 monotonic 时间和有界源码读取。`AnalysisLimitError(ValueError)` 由 Python 文件解析器显式重新抛出，不能被当成普通语法错误吞掉。Git 超时单独报告。

五个核心 JSON 顶层新增 `resource_limits` 对象，包含承诺值及 `timeout_kind: "cooperative"`。不要与现有 `analysis.limits` 的分析限制列表混用。HTML 的 map 数据同时保留资源说明。

60 秒是协作式检查点预算，不是 native parser 的强制中断保证；源码字节上限也不是整个进程 RSS 上限。文档不得声称硬实时或硬内存隔离。只有真实复现单文件 native parser 卡住/崩溃时，主代理再制定独立进程方案，不预先增加复杂设施。

规模实验使用自有静态样本的 100/1,000 文件及少量真实仓库，记录五步总耗时与最慢阶段。在被记录的参考机上每条标准查询应在 60 秒内完成，五步调查总计不超过 120 秒；不把该数字推广成所有机器的性能保证。超过则分析瓶颈，先改善一次分析内重复遍历，只有证据必要才提出缓存变更。

## 7. 平台、实用价值和维护

- 正式承诺从 macOS、Linux 开始；Python 3.11–3.14。Linux 覆盖四个 Python 版本，macOS 覆盖 3.11 和 3.14 安装/核心流程；记录真实 runner 架构，不扩展到未运行的 ARM/x86 组合。
- 若某组合缺可安装的已固定 native wheel，优先缩小明确支持矩阵或由主代理安排依赖兼容工作，不能跳过后仍标记支持。
- Windows 明确未验收；不靠通用 wheel 文件名推断支持。
- 选三个未进入历史选择集的新公开仓库：Python、JS/JSX、TS/TSX 各一。固定 SHA，预先写真实调查问题，不执行目标代码或安装其依赖。
- 每份中文调查说明：定位了什么、实际路径/行号、确定与未知、工具省下的手工步骤及还需读的文件。不能以命令成功数量代替价值。
- 至少一个全新 Codex 会话从新 Skill 独立完成五步链；主代理用源码核对关键结论，记录人工纠偏次数。不能用当前会话熟悉的步骤模拟新人成功。
- 发布前必须有用户明确的许可选择。此前可做技术工作，但不猜测许可、不发布 1.0。商业许可需要用户提供适用文本/权利决定，主代理不代拟法律结论。
- 补齐仓库及 wheel 的许可/URL/语言描述，新增 CHANGELOG、兼容/支持政策和问题反馈模板。不承诺未配置的响应 SLA。

## 8. 发行与保护

V2 起使用 `1.0.0.dev1` 内部开发版本，避免修改后的包仍冒用公开 0.8.0。V7 冻结为 `1.0.0rc1`，必要时递增；所有门禁通过后变为 `1.0.0`。正式版本号改变后重新构建并验收最终产物，不将 RC wheel 改名发行。每份开发安装同时记录源码 SHA；同版本号不等于同 runtime。

执行证据集中到新的 `~/.local/share/ai-repo-doctor/evaluations/v1-product-closure-v1/`，每次运行新子目录；正式产物到 `~/.local/share/ai-repo-doctor/releases/v1.0.0/`。不能覆盖 0.8.0 或旧 benchmark 证据。

必须保存：源码 SHA、构建工具版本、wheel SHA256、安装位置、每条命令的实际及预期退出码、CI 对应 SHA、下载校验、最终部署及回滚回执。异常中断不能留下 `complete: true`。

公开发布前修复已确认的发布阻塞；非阻塞项必须有边界说明和后续条目。通过精确提交 CI 后发布 GitHub tag/release，重新匿名下载，校验并从下载件在新环境安装。最后更新本机入口、启用并验证新 Skill、复核保护清单。
