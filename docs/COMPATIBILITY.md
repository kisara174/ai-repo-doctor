# 1.x 兼容与升级政策

本页是 1.0 的交付合同；正式版本尚未发布。实际安装和平台边界见 [安装指南](INSTALL.md)、[平台矩阵](SUPPORT_MATRIX.md)。

## 稳定接口

1.x 承诺 [CLI 合同](CLI_CONTRACT.md) 中五个只读命令的现有公共参数、JSON 字段类型/含义、退出码、符号 ID 与物理行号约定。允许增加可忽略字段；消费者应按各命令 schema_version 解析并忽略未知字段，不依赖 JSON 排序、示例数量或人类文本格式。

符号 ID 依赖相对文件和限定名称，源码移动或改名可以改变 ID；分析结果只针对记录的源码身份，不能缓存后当作新源码证据。调用关系会随解析修复而变化，新增正确证据不保证旧结果数量不变。

内部 Python 类/函数、开发脚本、HTML 内部 DOM、截图布局和未列入公共合同的内部数据不是稳定 API。map 的公开产物和 JSON 合同仍按其声明执行；静态分析范围不等于完整运行时语义。

## 从 0.8 升级

| 变化 | 使用者操作 |
| --- | --- |
| 新 Skill repo-doctor-v1 与 installation.json | 新目录导出、明确 `--cli`、新 Codex 会话核对版本；保留旧 repo-doctor Skill |
| 绝对 CLI 绑定 | Skill 不跟随全局链接自动切换；升级或回滚时明确选择对应绑定 |
| 新 resource_limits 字段 | 旧消费者忽略新增字段，按 [资源说明](RESOURCE_LIMITS.md) 处理超限失败 |
| impact 深度 1–10 | 超出范围的参数返回 2，默认仍为 2；不能依靠无限遍历 |
| 读取与时间边界 | 总预算包括同次再次读取；协作式超时不是强制杀死底层解析器或 RSS 限制 |
| 安装目录与入口 | 新版本用新环境，验证后再切换；保留原环境和 previous-entry 记录 |

旧 Python 案件、快照与地图不批量重写，不冒充新版重新验证；读取旧报告保持历史版本和来源。改源码后重新采集证据；JS/TS 仍不进入 Python snapshot/case/findings 工作流。旧 scan、report、findings、diagnose 等可选接口保留兼容，用法见 [次级参考](LEGACY_USAGE.md)，不扩展为主要产品入口。

## 变更与弃用

影响稳定合同的弃用须先写入 CHANGELOG 和对应文档，说明替代方法、迁移步骤和受影响版本，并保留到下一个主版本再移除；修复错误输出不得掩盖兼容影响。新增破坏性合同应使用新 schema 或下一主版本，不在补丁版本静默改变类型/退出码。

平台新增或缩减必须更新 CI 与支持矩阵。未验证 Windows、Intel Mac、其他架构或未来 Python 版本不自动获得承诺。维护入口和反馈要求见 [SUPPORT](../SUPPORT.md)，不承诺 SLA。
