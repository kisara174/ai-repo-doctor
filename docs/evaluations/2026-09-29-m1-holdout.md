# M1 diagnosis quality gate: fresh repair cohort

Registered 2026-09-29 before any model response for this cohort was read.
This is a focused check of the existing Python CLI diagnosis path. It does
not revise the product prompt or claim a population-level accuracy estimate.

## Frozen input and review contract

`evaluation/diagnosis/m1-holdout-v1.json` contains three new bug/fixed pairs
from three repositories not used by earlier diagnosis cohorts:

The primary agent reviewed each repair diff and its upstream regression test.
Manifest labels name only the paired defect. A fixed snapshot is not certified
free of all other bugs. The six selected symbols resolve in the static index;
their changed lines fit the 120-line request budget. The license file is
byte-identical within each pair. The external repositories, tests, and
dependencies are read as source only and are not executed or installed.

The evaluator removes test-file blocks and test-origin call evidence for this
dataset, so a regression test name cannot reveal the label. No symptom text,
issue label, ground truth, or fix reference enters the model request. The
AnyIO supplementary symbol is declared identically for its bug and fixed
snapshots and uses the CLI's existing explicit-context mechanism.

The manifest is frozen at SHA-256
`e0c8e1f2d38c15478b933632e083613e020b6d4c81b68ee5557a6196596d71af`.
Any correction to the labels or source fingerprints before dispatch requires
a new manifest hash and an updated registration; after dispatch, preserve this
file and report the limitation instead.

## Request and stop rules

- One arm, one call per case, ordered bug then fixed per repair: six calls
  maximum. Use the product's existing prompt and `chat-json` transport,
  `deepseek-flash`, omitted thinking parameter, 120 source lines, 4,096 maximum
  output tokens, and the existing 64-KiB context and 256-KiB wire limits.
- Prepare from a clean committed analyzer checkout. Record the analyzer commit,
  plan hash, six context/request hashes, provider model, usage, and elapsed
  time. The runner must verify every clean pinned checkout before dispatch.
- Send only through the evaluator's explicit `--allow-network` path. No retry,
  fallback provider, prompt change, or extra context after results are seen.
  A provider or parse failure stops the sequence; report attempted, failed,
  and unattempted calls separately.
- Review every accepted and rejected finding against the pinned implementation,
  upstream repair, and regression test. An exact quote proves provenance only.
  Mark TP, FP, uncertain, or duplicate with a concrete source rationale;
  score only after every review row is filled. A TP requires the known trigger
  and wrong outcome on a buggy snapshot. Only an accepted TP is a useful
  product issue.

## Registered decision gate

The current diagnosis path meets this small cohort's usefulness gate only if
all six calls return parseable responses, at least two of the three known
defects produce an accepted TP, and no fixed snapshot has an accepted false
alarm. Report the invalid-response fraction and accepted TP/fixed-FP counts
even if the run stops early. A failure holds any claim that the default prompt
is accurate enough for unattended use; it does not undo the working v0.2
human-reviewed issue workflow. A pass would justify a broader independent
cohort, not a general accuracy claim.

Report provider-reported input/output tokens and an estimated **upper bound**
on USD cost per accepted TP. For this bound, price every input token as a cache
miss and every output token at the current peak `deepseek-flash` rates: $0.30
and $1.20 per million tokens, respectively, from the
[official pricing table](https://api-docs.deepseek.com/quick_start/pricing/)
checked on 2026-09-29. Divide total estimated run cost by accepted TP count;
if there is no accepted TP or usage is missing, mark the value undefined.
This is not a billing statement, because the evaluator does not retain cache
hit/miss token counts and prices can change.

## Result

The frozen offline plan covered all six clean pinned checkouts at analyzer
commit `9d09d3d2c86836d50705705128d0db5645465a7c`. Its plan SHA-256 was
`265f77199617e4054f9fb87d3e68d8c974b880a6143a8c39ab7fa4c324a665c5`.
The first and only online call, `httpx-2998-bug`, returned
`invalid_response/truncated` after 16.48 seconds. The provider reported 2,626
prompt tokens and 4,096 completion tokens, exactly the configured completion
cap. The run stopped as registered: **1/6 attempted, 1 failed, 5 unattempted**.
There was no usable model finding or source-review row. The observed failure
fraction is 1/1 among attempted calls; it is not a population estimate.

At the preregistered all-cache-miss peak rates, this single failed call has an
estimated upper-bound cost of **$0.005703**. Cost per useful accepted TP is
undefined because no TP was available. The usefulness gate was **not met**;
the default prompt's diagnostic accuracy and repaired-snapshot false-alarm
rate remain unmeasured on this cohort. We did not repeat its call or substitute
another cohort into this result.

The frozen request omitted the `thinking` field. DeepSeek's documented default
enables thinking, while its completion cap includes generated reasoning tokens;
the recorded response reached that cap. The exact reasoning-token split was
not retained, so the record establishes truncation but does not by itself
prove how many tokens thinking consumed. See the
[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)
and [thinking-mode guide](https://api-docs.deepseek.com/guides/thinking_mode/).
After this frozen run, commit `a2f11a7` changed the product CLI's `chat-json`
preview and live request to explicitly disable thinking. It did not change
this evaluation's input or result. A separate six-line local fixture then
completed one preview-locked CLI call with a parseable response and a
quotation-verified issue. That smoke confirms the revised transport and case
record path for one small request, not the M1 quality gate.
